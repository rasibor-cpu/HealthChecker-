4. PATIENT IDENTITY GATE DETAIL
================================================================================

The PatientIdentityVerifier implements a FAIL-CLOSED policy:

Reason Code                     Decision    Condition
------------------------------  ----------  --------------------------------
PATIENT_NAME_MISSING            REVIEW      No name found in document
PATIENT_IDENTITY_AMBIGUOUS      REVIEW      Profile has no name configured
PATIENT_NAME_MISMATCH           REJECT      Normalized names differ
PATIENT_DOB_CONFLICT            REVIEW      Name matches but DOB conflicts
PATIENT_SECONDARY_ID_CONFLICT   REVIEW      Name matches but sex/MRN conflicts
PATIENT_IDENTITY_MATCH          ACCEPT*     Name + secondaries all corroborate

* ACCEPT-eligible only — still requires MEDICAL_DOCUMENT_CONFIRMED classification.

Name normalization rules:
  - NFC Unicode normalization
  - Lowercase
  - Strip punctuation: , . - ' "
  - Collapse whitespace to single spaces
  - Handles "LAST, FIRST MIDDLE" and "FIRST LAST" formats
  - Middle-name omission tolerance (one side absent → tolerated)
  - Both sides have conflicting middles → MISMATCH
  - NO fuzzy/edit-distance matching

================================================================================
5. MEDICAL CLASSIFIER DETAIL
================================================================================

CONFIRMED requires:
  >= 2 distinct strong TEXT signals (from 50+ clinical keywords)
  OR >= 1 text + >= 2 filename + medical MIME

UNCERTAIN: intermediate evidence — always REVIEW, never ACCEPT

NOT_MEDICAL: no strong signals — REJECT

Strong text signals include (partial list):
  laboratory results, lab results, blood test, complete blood count,
  creatinine, hemoglobin, hba1c, reference range, specimen type,
  ordering physician, ecg, electrocardiogram, radiology report,
  discharge summary, lifelabs, labcorp, icd-10, ...

Weak-only signals (never trigger CONFIRMED):
  report, results, medical, health, hospital, clinic, doctor, patient

================================================================================
6. ACQUISITION PIPELINE
================================================================================

Per-attachment pipeline (9 gates):
  Gate 1: Extension check (rejects .zip, .exe, .docx, etc.)
  Gate 2: Size check (> 20 MB → REJECT)
  Gate 3: Pre-retrieval idempotency (message_id + attachment_id)
  Gate 4: Content retrieval (GmailConnectorProtocol.get_attachment_bytes)
  Gate 5: SHA-256 computation + content idempotency
  Gate 6: Medical classification (GmailClassifier)
  Gate 7: Patient identity field extraction from document text/JSON
  Gate 8: Patient identity verification (PatientIdentityVerifier)
  Gate 9: Atomic handoff to hc_intake/incoming/ (accepted only)

Handoff mechanism:
  Write to .hc313a_tmp_<pid>_<filename> in incoming/
  os.replace() to final filename (atomic on Windows NTFS same-volume)
  On failure: temp file deleted, attachment NOT marked acquired → retry on next scan
