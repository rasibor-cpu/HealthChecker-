================================================================
ROOT_CAUSE
================================================================
Authenticated GET /api/health-vault/timeline?unified=true&metric=heart_rate built the
full patient vault via build_timeline(), which called list_measurements(document_id=...)
once per document. VaultStore._read_index() decrypts the entire encrypted index on every
call. On the live Health Connect vault that N+1 decrypt stalled past the Cloudflare/S24
fetch deadline, so the browser reported TypeError: Failed to fetch.

Why Snapshot/Records/Trends still worked with the same Bearer token:
  Snapshot history is capped and reads observations, not one decrypt per document.
  Records/Trends return small JSON from a single index read + filter.

Contributing (not sufficient alone):
  openFiltered() clicked the Timeline tab (SCREEN_LOADERS loadTimeline) and then called
  loadTimeline() again → two concurrent huge unified-timeline GETs on S24.
  Each timeline entry embedded the full document blob, which _sanitize_value() walked
  before JSONResponse — large payload after a slow build.

Service worker on UAT12E already skipped /api/ (isForbiddenCacheUrl early return). An
older controlling SW wrapping /api/ in respondWith can also surface Failed to fetch for
slow/large API bodies; revision advanced to hc321uat12f and the non-intercept remains.
